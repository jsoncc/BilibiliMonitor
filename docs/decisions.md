# 架构决策记录

## ADR-001：第一版使用 SQLite

原因：第一版面向本地个人使用，监控对象不超过约 20 个，SQLite 足够简单且数据库文件可直接放入项目目录。

## ADR-002：后端负责采集

原因：浏览器关闭后仍需持续采集；同时避免前端直接暴露 Cookie 和处理跨域问题。

## ADR-003：默认轮询而非 WebSocket

原因：数据采集本质上依赖定时请求，第一版使用简单可靠的定时任务和前端刷新，后续再考虑 SSE/WebSocket。

## ADR-004：历史趋势由快照计算

原因：哔哩哔哩通常返回当前值，不直接提供任意视频的完整历史曲线，因此本项目保存带时间戳的成功采样点。
