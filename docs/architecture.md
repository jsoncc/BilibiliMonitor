# 架构说明

前端 Vue 3 负责展示和每分钟刷新；FastAPI 负责解析输入、调用数据源、保存快照和提供趋势 API；APScheduler 在后端进程内执行自动采集；SQLite 保存项目目录 `data/` 下的历史数据。

前端按职责拆分为 `SearchBar`、`MonitorSidebar`、`MetricGrid`、`FocusMetricPanel` 和 `TrendPanel`，`App.vue` 负责页面状态编排。状态流转为：空白 → 搜索中 → 预览 → 仅查看/监控/历史；搜索错误和采集错误均在页面内反馈。

对象详情可在全部指标与专注模式间切换。专注模式是单对象沉浸视图，前端隐藏搜索、对象导航、采集控制和趋势区；专注配置以 `targets.focus_metrics` JSON 数组按对象保存，通过 `/api/targets/{id}/focus` 更新；三连总量在前端由点赞、投币、收藏实时合计，不改变采集、快照或趋势数据流。

专注面板独立请求最近 168 小时趋势点，在前端计算最新两次采集、24 小时和 7 天三个变化窗口。百分比以窗口基准值计算；历史覆盖不足时显示实际记录时长，不新增后端接口或快照字段。

趋势区由时间范围、指标和图表模式共同控制：范围对应 24/168/720 小时，指标一次只绘制一个，增长模式以窗口首点为基准，总量模式显示平台返回值。

图片由后端标准化为 HTTPS 地址，前端通过本地 `/api/media/image` 代理加载；代理只允许 `*.hdslb.com` 图片域名，失败时由统一图片组件显示占位，不影响监控数据采集。

UP 主采集使用公开账号统计接口，当前范围为粉丝、投稿数和关注数。为避免无效请求和平台访问限制，v0.1 不采集“上次投稿日期”；如未来存在正式授权数据源，将作为独立能力接入。

数据流：浏览器输入 → 后端预览 → 用户确认 → 数据源适配器 → 成功快照入库 → 趋势 API → ECharts。仅查看一次走临时查询链路，不进入监控任务。监控任务不依赖浏览器页面持续打开，只依赖后端进程运行。

采集任务使用每对象异步锁避免重复采集；失败最多重试两次，退避 5 秒和 15 秒，最终失败记录日志并延长下一次采集时间。

SQLite 启用 WAL、外键和 5 秒 busy timeout，降低采集写入与趋势、日志、导出读取同时执行时的锁冲突。导出由后端即时生成 CSV/JSON 响应，不在项目目录保存副本。

没有历史快照的对象会从首次成功采集时间开始形成趋势。采集失败不会写入快照；历史快照默认永久保留。
