## 文档维护规则

- 新增功能：同步更新产品需求、版本规划、当前状态和变更记录。
- 修改技术实现：同步更新技术架构、API、数据模型或开发指南。
- 修复问题：同步更新变更记录和测试计划。
- 未完成或暂缓事项必须明确写入当前状态，不用“已完成”表述。
- 文档中的实现状态以代码和实际验证结果为准。
- 文档优先记录决策、接口、约束、状态、验收结果和变更原因，避免重复代码说明。
- 同一事实只保留一个权威来源，其他文档通过链接引用，不复制整段内容。
- 开发过程中发现过时、重复或无实际价值的内容，应同步合并、删除或改写。
- 文档应短而准确；不写无法验证的承诺、背景套话和与实现无关的废话。
