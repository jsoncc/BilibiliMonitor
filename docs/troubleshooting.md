# 故障排查

- 无法采集：检查网络、接口返回和后端终端日志。
- 需要登录态：在根目录 `.env` 配置 `BILIBILI_COOKIE` 后重启后端。
- 前端无法请求后端：确认 8000 端口运行，且前端 Vite 代理配置未被修改。
- 趋势为空：对象刚创建时只有一次采样，等待下一次自动采集。
# Cookie 配置

当前版本不采集“上次投稿日期”，UP 主监控范围为粉丝、投稿数和关注数。部分公开接口可能受平台访问限制；如确有需要，可在项目根目录 `.env` 填写完整 `BILIBILI_COOKIE` 后重启后端。

`.env.example` 只是模板，不要直接填写；请复制为项目根目录的 `.env`。Cookie 只保存在本地，不要提交到 Git 或发送给他人。

# 导出与数据库文件

- 导出失败：确认后端仍在 `8000` 端口运行，并检查浏览器是否允许下载文件；导出只读取本地快照，不会访问外部接口。
- `data/` 下出现 `bilibili_monitor.db-wal` 或 `bilibili_monitor.db-shm`：这是 SQLite WAL 的正常运行文件，不要单独删除。关闭后端后如需迁移或备份数据库，应将数据库主文件与这两个文件一并复制。
- 历史数据默认永久保留。需要减小体积时，先导出所需数据，再由后续维护功能进行人工清理；当前版本不会自动删除快照。
