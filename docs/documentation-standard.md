# 文档维护规范

## 原则

- 以当前代码和验证结果为准。
- 只记录会影响开发、测试、运行或决策的内容。
- 一个事实只保留一个权威文档。
- 需求、实现、测试和变更必须能互相追溯。

## 更新规则

| 变化 | 必须同步的文档 |
|---|---|
| 新增产品功能 | 产品需求、版本规划、当前状态、变更记录 |
| 修改接口 | API 文档、测试计划、变更记录 |
| 修改数据库 | 数据模型、技术架构、测试计划 |
| 修改部署方式 | 技术架构、根目录 README、运维排障 |
| 修复缺陷 | 当前状态、变更记录、相关测试 |
| 技术方案调整 | 架构决策记录、技术架构、版本规划 |

## 精简标准

- 删除重复段落和已经失效的内容。
- 优先使用表格、清单和短段落。
- 不在多个文档复制完整接口定义；统一引用 API 文档。
- 不把临时讨论、猜测和未验证信息写成结论。
- 每次更新保留必要的日期和变更原因。
